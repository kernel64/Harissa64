# Third-party code and data

Harissa64 V2 is licensed under the GPL v2. Code or data not written for this project is listed here with its origin and licence.

| What | Where | Origin | Licence |
|---|---|---|---|
| 8x8 bitmap font (`font8x8_basic`, U+0000–U+007F) | `platform/xbox360/font8x8_basic.h` | Daniel Hepper, https://github.com/dhepper/font8x8, based on Marcel Sondaar's font8x8 and IBM's public-domain VGA fonts | Public domain |
| CIC-NUS-6105 challenge/response algorithm | `core/pif/h64_pif.cpp` (`cic_6105_response`) | X-Scale (2011), as distributed with mupen64plus (`n64_cic_nus_6105.c`) and Harissa64 V1; rewritten in the V2 style, same algorithm and tables | BSD 2-clause (notice kept in the source) |
| RSP interpreter: scalar unit, vector unit (scalar "SISD" paths), reciprocal tables, SP DMA and registers | `core/rsp/` | ares, `ares/n64/rsp/` (`interpreter*.cpp`, `dma.cpp`, `io.cpp`, `rsp.cpp`) at commit `a776c509`, ported to the V2 C++ subset; pipeline timing (issue groups, dual issue, stalls, per-instruction register use from `decoder.cpp`, `Pipeline` in `rsp.hpp`, `instruction()` in `rsp.cpp`) at commit `652d6537` | ISC (below) |
| Software RDP: command decoding, span setup, coverage, interpolation, perspective divide, texture sampling and LOD, combiner, blender, depth test, dither, noise, framebuffer formats | `core/rdp/h64_rdp_render.cpp`, `core/rdp/h64_rdp_tex.cpp`, `core/rdp/h64_rdp_state.h` | ParaLLEl-RDP (Themaister/parallel-rdp, commit `1cecd042`): `rdp_device.cpp`, `rdp_renderer.cpp` and the compute shaders, ported to serial C++ (TMEM loads rewritten as the hardware walks them) | MIT (below) |
| Blender divider and VI gamma tables | `core/rdp/h64_rdp_luts.h` | ParaLLEl-RDP `parallel-rdp/luts.hpp` (same commit), data generated from it | MIT (notice in the file and below) |
| Audio task HLE: alist ABIs (audio, naudio, nead variants), MusyX v1/v2, MP3, audio helpers, task detection | `core/hle/h64_hle*.cpp` | mupen64plus-rsp-hle (https://github.com/mupen64plus/mupen64plus-rsp-hle, commit `8a7a472`, June 2026): `alist*.c`, `audio.c`, `musyx.c`, `mp3.c`, `hle.c`; the copyright headers are kept in the files. Adapted to V2: C++ subset, guest memory in N64 byte order through endian helpers, `alist_filter` made host-independent, envmixer state blobs with explicit field accessors | GPL v2 or later |
| RDP triangle setup (edge, shade, texture and depth coefficients from three vertices) | `core/rdp/h64_rdp_trisetup.cpp` | libdragon (https://github.com/DragonMinded/libdragon, commit `e356bf3`), `src/rdpq/rdpq_tri.c` (CPU reference setup), in double precision | Public domain (Unlicense) |
| Save type per cartridge (header CRCs, save type, Controller Pak) | `core/cart/h64_savedb.inc` (generated by `tests/scripts/gen_savedb.py`) | mupen64plus-core's ROM catalogue `mupen64plus.ini`, as shipped by Harissa64 V1 (`master:files/mupen64plus.ini`) | GPL v2 or later |
| FlashRAM command set and status words; formatted Controller Pak image | `core/cart/h64_save.cpp` | mupen64plus-core (`device/cart/flashram.c`, `device/controllers/paks/mempak.c`), studied and rewritten; pak layout and checksums as documented on n64brew | GPL v2 or later |
| zlib 1.3.1 (inflate, CRC-32, adler32 only; built with `Z_SOLO`), for zipped ROMs | `third_party/zlib/` (unmodified, `LICENSE` and `README` kept) | https://zlib.net, the copy Harissa64 V1 ships (`master:source/zlib/`) | zlib licence |
| PIF boot ROM state for running the real 6105 IPL3 (IPL3 in DMEM, IPL2's last 8 words in IMEM, s3-s7, t3, sp, ra) | `core/pif/h64_pif.cpp` (`ipl3_boot`) | mupen64plus-core `device/pif/bootrom_hle.c` (`pif_bootrom_hle_execute`), studied and rewritten | GPL v2 or later |
| RDRAM module registers (power-on values, device ID / address-select matching, broadcast, inverted mode bits, reads lost while a module calibrates) and the RI address mapping | `core/system/h64_devices.cpp` (`rdram_*`, `h64_rdram_read_lost`) | mupen64plus-core `device/rdram/rdram.c`, `device/rcp/ri/ri_controller.h`, studied and rewritten | GPL v2 or later |
| PI DMA block model and duration formula | `core/system/h64_devices.cpp` (`pi_dma`, `pi_dma_cycles`), PI bus address after CPU accesses in `core/memory/h64_bus.cpp` | ares, `ares/n64/pi/dma.cpp`, `io.cpp`, `bus.hpp` (https://github.com/ares-emulator/ares, master, October 2026), followed closely | ISC (below) |

The graphics HLE (`core/hle/h64_gfx.cpp`: microcode detection (including the CRC table that identifies Rare's microcodes and the way it is computed), Rare's F3D variants (GoldenEye, Perfect Dark, Diddy Kong Racing / Jet Force Gemini: `F3DGOLDEN.cpp`, `F3DPD.cpp`, `F3DDKR.cpp` and their `gSP.cpp` helpers), command encodings of F3D/F3DEX/F3DEX2/F3DZEX, matrix stack, lights, viewport, texture generation, fog, branch and cull commands) follows GLideN64 (https://github.com/gonetz/GLideN64, commit `41c7ba2`, GPL v2): studied and rewritten, no renderer code taken. The Xenos renderer's mapping of blender modes to GPU blending is modelled on GLideN64's approach in the same way.

Behaviour learned from test ROMs is credited in comments but no code is taken from them: n64-systemtest (Lemmy, MIT; studied, never copied), angrylion-rdp-plus (MAME licence, not GPL-compatible: not studied for code), Dillonb/n64-tests (no licence stated) and PeterLemon/N64 (Unlicense). The ROMs themselves are downloaded by `tests/scripts/fetch_test_roms.py` and never committed.
